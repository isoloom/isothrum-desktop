# Isothrum desktop

The Isothrum editor in a window, plus what a browser can't do: **run a lab on this machine**,
**open a console** on its machines, **start, stop and snapshot** them, and **capture traffic**.

- **The editor is bundled** (`editor/`, built from the website by `npm run editor`): the app
  works offline. Accounts and saved projects live on isothrum.com: set
  `ISOTHRUM_URL=https://www.isothrum.com/en` to use the site in the window instead.
- **Run / Stop**: the lab's `isoloom.yml` and its Docker Compose files (generated by Isoloom's
  library, no CLI needed) are written to the app's data folder, then `docker compose up`.
  A lab with VMs runs with **Vagrant** instead: Isoloom's Vagrant output when every machine is
  a VM, its hybrid one when VMs and containers mix (the containers in a Docker host VM). The
  lab's own files (provisioning scripts, appliance configurations) are written next to it.
- **Console**: a terminal on a machine: a shell in its container, SSH to a Cisco appliance's
  management address (`admin`/`admin`, from a helper container on that network), or `vagrant ssh` to a VM. The terminal is `$TERMINAL`, else GNOME
  Terminal, Konsole, Xfce Terminal, Alacritty, `x-terminal-emulator` or xterm (Terminal.app on
  macOS, cmd on Windows).
- **Screen (VNC)**: what a machine shows, in a viewer here, as GNS3's VNC console. A container whose
  image runs a VNC server (it exposes a port in 5900–5999) is reached through a forwarder container
  publishing it on 127.0.0.1 (container addresses aren't reachable from the host under Docker
  Desktop), opened as `vnc://` (Screen Sharing on macOS); a VirtualBox VM opens its own screen
  window, a libvirt VM its VNC or SPICE display. Stopping the lab removes the forwarders.
- **In the editor**, as in GNS3: double-click a running machine for its console, right-click it
  for its console, its screen, and starting, stopping or restarting it.
- **Start, stop, restart** one machine, with its network sidecar (its routes come back).
- **Auto-start**: a lab set to it (in the Run window) starts when the app opens on it, unless it is
  running already.
- **Live status**: while the lab runs, each machine shows its state on the canvas (a dot: running,
  starting, unhealthy, stopped; with its health when its image has a check), each cable whether it
  carries traffic, is suspended or down, and each LAN how many of its ports are up. The ports are
  read from the machines every few seconds: one throwaway container (`nsenter`, privileged, in
  the host's PID namespace) lists each running machine's links. A lab with VMs isn't probed: its
  ports follow the machines' states and the suspended links.
- **Suspend / resume a link**: a cable's ends (or every link of a LAN) set down in the machines'
  network namespaces, as pulling the cable would, and up again with their routes (the machine's
  routes sidecar restarted; a VM's `routes` provisioner run again). A cut link stays cut through
  a restart of the machine, or of the lab, until the lab stops. A Cisco appliance's own port
  can't be cut (its OS owns the address): a cable to one is cut at its other end.
- **Snapshots**: a container saved as an image (`docker commit`: its files, a router's saved
  configuration; not named volumes), restored by running the machine from it; a VM's are
  Vagrant's (`vagrant snapshot`).
- **Capture traffic** on a LAN or a cable: a throwaway container (`nicolaka/netshoot`) joins
  the network namespace of a machine on that segment, finds the interface by its address, and
  streams `tcpdump` live into Wireshark, or into a `.pcap` file when Wireshark isn't installed.
  In a lab with VMs, `tcpdump` runs in a VM on the segment over `vagrant ssh` (installed if
  missing), or for a container, in the capture image on the Docker host VM.
- **Updates**: the app checks GitHub's latest release (signed with the app's update key) and
  offers to restart on a newer one.

The editor shows these controls only when it finds the app's bridge (`window.__TAURI__`). Only
the bundled editor and isothrum.com may call the app's commands (`src-tauri/capabilities/editor.json`);
debug builds also allow `http://localhost` for a local build of the site (`src-tauri/src/capabilities.rs`).

## Needs

Docker, usable by your account (Linux: `sudo usermod -aG docker $USER`, then log in again).
For labs with VMs, Vagrant with VirtualBox or libvirt (`vagrant-libvirt`).
Wireshark, to watch captures live.
The app finds them on the PATH, and also in their usual folders when the PATH doesn't say: on
macOS `/usr/local/bin`, `/opt/homebrew/bin` and Docker's and Wireshark's app bundles (an app
started from Finder gets a minimal PATH), on Windows `Program Files\Wireshark`.

## Develop

```
npm install
npm run editor                                       # the bundled editor, from ../../../isothrum-website
                                                     # (or ISOTHRUM_WEBSITE=/path/to/isothrum-website)
npm run dev                                          # the app on the bundled editor
ISOTHRUM_URL=http://localhost:3000/en npm run dev    # against a local build of the website
cd src-tauri && cargo test                           # the app's tests
cd src-tauri && sg docker -c "cargo test -- --ignored"   # its tests that need Docker (and Vagrant)
npm run build                                        # .deb / AppImage / .dmg / .msi
```

## Release

Push a tag (`git tag v0.2.0 && git push --tags`): `.github/workflows/release.yml` builds the
installers for Linux, macOS (universal) and Windows on a **draft** release, with `latest.json`
for the updater. Publish the draft when it looks right.

Secrets of the repository (Settings → Secrets → Actions):

| Secret | What |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | The update key (set). Its public half is in `tauri.conf.json`; keep the private one backed up (it was generated into `~/.isothrum/updater.key`). |
| `WEBSITE_REPO_TOKEN` | A read-only token for `isoloom/isothrum-website` while it is private (the editor is built from it). |
| `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY` | The Developer ID Application certificate (.p12, base64), its password, its name. |
| `APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID` | Notarization: the Apple ID, an app-specific password, the team. |
| `WINDOWS_CERTIFICATE`, `WINDOWS_CERTIFICATE_PASSWORD` | The code-signing certificate (.pfx, base64) and its password. |

Builds are unsigned (for macOS and Windows) until those secrets exist. The updater downloads
from GitHub releases: it works once the repository is public.

A local *production* build of the website served over http needs `LOCAL_HTTP=1` at build time:
WebKit doesn't exempt localhost from `upgrade-insecure-requests`.
